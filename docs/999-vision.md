# Vision: パーソナル文脈による生活キュレーター

**最終更新**: 2026-05-10
**ステータス**: 構想段階（要件定義書 v1.6 のMVPの先にある最終形）

---

## このドキュメントの位置づけ

これは要件定義書（実装契約）ではなく、**長期ビジョンを記録するドキュメント**である。
MVP実装中の判断軸として参照するためのもので、ここに書かれていることをすぐに実装する必要はない。

要件定義書は v1.6 のMVPスコープを守る。このビジョンはPhase 2のさらに先、もしくは別プロジェクトとして検討する。

---

## 核となるビジョン（自分の言葉）

> コンテキストとして好きな本、音楽、場所を溜めていって、
> そこから新たな提案をもらうという生活を豊かにする

## ビジョンの本質

このアプリの最終形は、以下のような性質を持つ:

- **静的な記録媒体ではなく、動的な提案システム**である
- 蓄積したコンテキストが**自分自身を理解する装置**になる
- そこから**生活を豊かにする次の一歩**が提案される
- 言うなれば「**自分という文脈で動くAIキュレーター**」

これは「パーソナル雑誌」というメタファーで言い表されることもある。雑誌が編集者の美意識で世界を切り取るように、このアプリは自分の美意識でコンテンツを編集・蓄積し、そこから新しい発見を引き出す。

## 美意識のドメイン

このアプリが扱う領域は、自分の生活の中で大切にしているもの:

- ジャズ（音楽 / レコード / ライブ / ミュージシャン）
- 文学（本 / 作家 / 文学にまつわる場所）
- ジャズバー、ジャズ喫茶
- コーヒー
- フランスのテラスカフェ、ヨーロッパの街並み
- そして、これらが交差する場所での体験

## 集めるべきコンテキスト

「好きなもの」として蓄積する対象:

| カテゴリ | 例 | 持つべき情報 |
|---|---|---|
| 音楽 | アルバム、アーティスト、楽曲 | タイトル、購入/聴取日、所感、評価 |
| 本 | 単行本、雑誌、エッセイ | 著者、読了日、引用、所感 |
| 場所 | ジャズバー、喫茶店、書店、街 | 位置、訪問日、印象、誰と行ったか |
| 体験 | ライブ、展覧会、旅行 | 日付、場所、誰と、何を感じたか |
| 言葉 | 引用、フレーズ、詩の一節 | 出典、書き留めた日、なぜ心に残ったか |

これらすべてに共通する構造: **何か(モノ/場所/体験) + それにまつわるストーリー(メモ・タグ・関係性)**

## 期待する提案の例

蓄積されたコンテキストから引き出されるべき提案:

- 「最近Kenny Burrellを聴いてるなら、横浜のジャズバー○○がBlue Note系の選曲で良さそう」
- 「○○（作家）を読んでるなら、その作家が通った場所として✕✕（カフェ）が現存する」
- 「先月行った京都の喫茶店、Bill Evans系の音楽が好きな人が集まる雰囲気だった。次は△△あたりが似た雰囲気」
- 「Avishai Cohenの新譜が出た。あなたは2年前に彼のライブに行って、その時のメモに『ベースの低音が体に響いた』とある。今度の来日は2025年12月、Blue Note Tokyo」
- 「Paris旅行の際、あなたが好きなSaint-Germain-des-Présの周辺で、文学にゆかりのあるカフェ巡りプラン」

## 他にない価値

このアプリが既存のサービス（Goodreads、Discogs、Notion等）と違うのは:

1. **複数ドメインの横断**: 音楽・本・場所が同じ文脈に共存する
2. **個人の美意識への強いフォーカス**: SNSのような社会的承認の文脈がない
3. **能動的提案**: 蓄積したデータから次の体験を提案する
4. **静かさ**: 通知の嵐ではなく、開いたときに自分と向き合える場所

## 段階的なロードマップ

### Phase 1（現在のMVP）
- ジャズアーティストの新譜・公演フィード
- アナログレコードコレクション
- アーティスト管理

### Phase 2（コレクション機能の充実）
- 本のコレクション機能
- データモデルの一般化（汎用「コレクション項目」）
- メモ・タグの強化

### Phase 3（場所機能）
- 行きたい場所・行った場所の記録
- 位置情報、地図表示
- 訪問履歴と所感

### Phase 4（横断と発見）
- 全コレクションの全文検索
- タグによる横断的な探索
- 「この本を読んでた頃、こんなレコードを買っていた」のような時系列での自分の文脈の振り返り

### Phase 5（提案システム）
- LLMベースの提案エンジン
- ベクトル検索による類似性発見
- 「あなたの文脈ならこれが好きそう」の生成
- 旅行プラン、読書リスト、ライブの提案

### Phase 6（編集と発信）
- 自分のコレクションから「特集」を編集する機能
- 雑誌的なレイアウトでの閲覧
- （任意）親しい人と共有

## 設計上の含意（MVPに対する伏線）

このビジョンを念頭に置くと、MVP実装中も以下を意識すると良い:

- **データモデルの一般化可能性**: `vinyl_records` のスキーマを後で `books` や `places` に拡張しやすい構造にしておく（基底クラス化、共通カラムの抽出など）
- **メモ機能の重要性**: ストーリーは横断的な検索の基盤になる。ストーリーを書きたくなるUI/UXに投資する価値がある
- **タグの可能性**: MVPには含めないが、将来的にコレクション横断の探索でタグが鍵になる
- **時系列データの保持**: `created_at`、`updated_at`、`purchase_date` 等、時間軸の情報は将来の振り返り機能で価値を持つ
- **画像のローカル保存**: 外部URLは時間とともに切れる。長期保存を見据えるなら画像はローカル化したい

## やらないこと

このビジョンの実現に向けて、明確に避けるもの:

- **SNS機能**: いいね・フォロー・コメントは入れない。社会的承認の場ではない
- **広告・収益化**: 自分のためのものなので、広告で価値が薄まることはしない
- **他人のおすすめ**: 推薦は「自分の文脈から」生まれるべきで、トレンドや人気で動かない
- **ゲーミフィケーション**: コレクション数を競うアプリにはしない
- **過剰な通知**: 静かに開いて自分と向き合う場所を保つ

## 自分への問いかけ

このアプリが完成して数年使い続けたとき、自分に対してこう答えられるとよい:

- このアプリは私の「好き」を覚えてくれている
- 開くたびに、自分が何を大切にしてきたかを思い出せる
- 次の週末、何をしたいか、ここを見ればヒントがある
- 大事な場所、レコード、本のひとつひとつに、自分だけのストーリーがある
- これは私の生活の編集者だ

## 補足: なぜこれを書き残すのか

エンジニアリング上、要件定義書には実装に直結することだけを書くべきだが、ビジョンは実装よりも長く生き続ける。

MVPを作っている最中に「ここを一般化しておけば後でレコード以外にも使えるな」という気付きが出たとき、このドキュメントが判断軸になる。

逆に、MVPでは過剰な一般化はしない。具体的なものを作りながら、抽象を見出していく順序を守る。

「コンテキストとして好きな本、音楽、場所を溜めていって、そこから新たな提案をもらう」──このシンプルな一文を、忘れずに開発を進めていく。
